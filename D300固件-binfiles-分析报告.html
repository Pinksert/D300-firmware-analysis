一、总体结论

这是 Nikon D300 数码单反 Ver.1.11 固件升级包解包后的两个主体镜像文件。尼康把相机固件拆成两块独立烧写的映像：

  • Firmware A（A3000111.bin）——主控 CPU 的程序代码映像，512 KiB。里面是 Fujitsu FR 系列处理器的机器码、RTOS 内核、引导与升级逻辑，以及用于固件校验/解密的 CIPHERUNICORN-S 密码库。
  • Firmware B（B3000111.bin）——资源/数据映像，7 MiB。里面是菜单 UI 的多语言文本表、图像处理参数表、ICC 色彩配置文件、DPOF/PictBridge 打印脚本、GPS 与无线传输（WT-4）相关字符串，以及一块高熵压缩数据。

两个文件均未加密，尾部各带 2 字节 CRC-16 校验，且校验值完全匹配，说明文件完整未被篡改。

二、校验和机制（已验证）

两个文件的最后 2 字节是 CRC-16 校验值，算法为 CRC-16/CCITT-FALSE（多项式 0x1021，初值 0x0000，非反射，无输出异或），以大端序存放，覆盖范围是整个文件除最后 2 字节外的全部数据。

五、与 D300SUpdate/D300S102.bin 的对比

同目录下的 D300SUpdate/D300S102.bin 揭示了尼康固件打包方式的演进：

项目D300 (V1.11)D300S (V1.02)
文件数2 个（A + B 分开）1 个（A + B 合并）
总大小0x80002 + 0x7000000x780002
关系0x700000 (B) + 0x80000 (A) + 2 (CRC) = 0x780002 ✔ 完全吻合
内容明文，可直接看到字符串与代码已加密/混淆，开头为 32 字节 0x20 填充 + Pr1 魔数，其后为高熵数据
CRC 验证通过不适用（密文上 CRC 不匹配，说明 CRC 在加密前计算或对明文计算）

而 A 固件中携带的 CIPHERUNICORN-S（NEC）密码库，正是尼康从这一代产品开始引入的固件加密体系——同一份 A 固件里既有用于校验新版加密固件的解密例程，也解释了为什么 D300S 之后的 bin 文件不再是可读明文。
